# 주간영업일지 데스크톱 앱 (시제품 v0.2)

기존 영업일지 화면을 **PC 안에서 바로 여는** 프로그램입니다. 화면은 한 번 받으면 PC에 저장해 두고(서버를 다시 부르지 않음),
글·사진 저장은 기존 서버(Apps Script)로 그대로 보냅니다. **기존 화면 코드(`gen_journal4.py`)는 고치지 않았습니다.**

## 구조

```
앱 창(pywebview) ─▶ 내 PC 안의 작은 서버(127.0.0.1) ─▶ 기존 서버(Apps Script)  ← 나중에 "PC 서버"로 교체
                         │
                         └─ 화면 저장소: %LOCALAPPDATA%\WJApp\cache\   (저장본이 있으면 서버를 기다리지 않고 바로 열고, 뒤에서 새로 받아 둠)
```

- 화면 안의 서버 주소를 앱 주소(`/api`)로 바꿔서 보냅니다. 화면은 자기가 앱 안에 있는지 모릅니다.
- **로그인 열쇠(토큰)는 앱만 들고 있습니다.** 화면 안 자바스크립트에는 자리표시자(`app`)만 넘기고, 서버로 보낼 때 앱이 진짜 열쇠를 붙입니다.
- 앱의 내부 서버는 `127.0.0.1`에서만 열리고, **앱 창이 가진 열쇠(쿠키)가 없으면 403으로 막습니다.** (같은 PC의 다른 프로그램이 내 로그인을 쓰지 못하게)
- 서버가 안 되면 저장해 둔 화면(조금 오래된 것)이라도 엽니다.
- **v0.2**: 저장본을 3일까지 '먼저 바로' 열고 5분 넘었으면 뒤에서 새로 받습니다. 화면 오른쪽 아래 **↻ 최신 데이터 받기** 버튼으로 즉시 새로 받을 수 있습니다. 호출마다 걸린 시간이 화면(콘솔)과 `%LOCALAPPDATA%\WJApp\app.log` 에 남습니다. 같은 화면을 동시에 부르면 서버는 한 번만 부릅니다.
- 로그인은 서버 규칙대로 **1일** 유지됩니다. 로그인 정보는 `%LOCALAPPDATA%\WJApp\session.json`에 저장됩니다(시제품: 암호화 전).

## 지금 실행해 보기 (윈도우)

```powershell
cd "<이 폴더>\desktop_app"
pip install -r requirements.txt
# 서버 주소: 아래 셋 중 하나 (우선순위 순)
#   1) python wj_app.py --api-url "https://script.google.com/macros/s/.../exec"
#   2) 환경변수 WJ_API_URL
#   3) api_url.txt 파일 (이 폴더 / %LOCALAPPDATA%\WJApp / ..\apps_script\weekly_journal\api_url.txt ← 반영 프로그램이 쓰는 것과 같은 파일)
python wj_app.py --browser     # [시험 모드] 일반 브라우저로 열림. 앱 창이 아님 (앱 창 문제와 화면 문제를 나눠서 볼 때만)
python wj_app.py               # [앱 모드] 주소창 없는 독립 앱 창으로 열림 (pywebview 필요)
python wj_app.py --reset       # 저장된 로그인·화면 지우고 시작
```

## 바탕화면 바로가기 (더블클릭하면 앱이 바로 열림)

```powershell
cd "<이 폴더>\desktop_app"
powershell -ExecutionPolicy Bypass -File .\make_shortcut.ps1
```
바탕화면에 **영업일지** 아이콘(웃는 수첩)이 생깁니다. 검은 창 없이 앱 창만 열립니다(`pythonw`). 서버 주소가 없는 등 시작할 수 없을 때는 메시지 창으로 알립니다.
아이콘은 `wj_app.ico` (다시 만들려면 `python make_icon.py`, Pillow 필요).

`.exe` 로 만들기: `.\build_exe.ps1` → `dist\WJApp.exe`

## 나중에 "PC 서버"로 바꿀 때

| 바꿀 것 | 방법 |
|---|---|
| 서버 주소 | `api_url.txt` 의 주소만 새 PC 서버 주소로 |
| 요청 형식 | 새 서버가 지금과 같은 요청(`{a:'login'/'page'/'pull'/'saveMany'…}`)에 같은 모양으로 답하면 **앱은 수정 없음**. 다르면 `wj_app.py` 의 `upstream()` 한 곳에서 변환 |
| 화면 올리는 곳 | `pipeline.py` 가 화면을 올리는 곳을 PC 서버로 (앱은 모름) |

## 시제품에서 아직 없는 것 (다음 단계)

- 자동 업데이트 (지금은 `WJ_MIN_VERSION_URL` 로 낡은 버전 차단만 가능)
- 로그인 정보 암호화 저장 (윈도우 자격 증명 보관소)
- 사진 올리기 개선 (원본 화질 → 파일 저장소)
- **글 저장 재시도 안전장치**: 저장은 응답이 끊겼을 때 자동 재시도하지 않습니다 (이미 저장됐는데 충돌로 보이는 것을 막기 위해). 서버에 요청 번호(중복 방지)가 생기면 추가
- 로그인 입구 구분(`site`: HK/TW/HQ): 지금 앱은 보내지 않아 입구 제한 없이 계정 권한대로만 동작
- `매장` 탭: 서버에 아직 없는 화면이라 앱에서도 열리지 않음

## v0.3 — 화면을 바꿀 때 빨라지는 이유 (글 데이터 저장본)

화면을 바꿀 때마다 화면 안의 스크립트가 **일지 글·사진(`pull`/`pullMany`)과 지난 주 목록(`archive`)을 서버에 새로 물었고**, 앱은 이를 저장하지 않고 그대로 전달했습니다(그래서 화면은 저장본으로 열려도 글이 채워지는 데 서버 시간이 걸렸습니다). v0.3부터 이 데이터도 PC 에 저장합니다.

| 상황 | 동작 |
|---|---|
| 같은 데이터를 15초 안에 다시 요청 | 서버를 부르지 않고 저장본으로 바로 답함 |
| 30초 넘게 안 부르다가 요청(= 화면을 새로 열거나 이동) | 오래됐어도 **저장본을 먼저 바로** 주고, 뒤에서 새로 받아 둠 |
| 30초 안에 되풀이되는 요청이 15초보다 오래된 저장본에 대한 것 | 화면이 주기적으로 확인하는 것으로 보고 서버에서 받음 (다른 사람이 고친 것을 놓치지 않게) |
| 저장·마감 | 항상 서버로 감(버전 충돌 검사는 서버가 함). 성공하면 저장본도 바로 고침. 충돌이 나면 서버의 최신 내용으로 고침 |
| 미리 받기 | 로그인/실행 시 지난번에 쓴 글 데이터를 먼저 새로 받아 둠. 받아 온 화면 안의 법인·주차(`sumfill`)를 읽어 그 화면이 요청할 글 데이터도 미리 받음 |
| `↻ 최신 데이터 받기` | 그 화면과 저장해 둔 글 데이터를 모두 서버에서 새로 받음 |
| 인터넷이 안 됨 | 오래된 저장본이라도 보여 줌 (`stale`) |

- 저장본은 **로그인한 사람별**입니다(같은 PC 를 다른 계정이 쓰면 보이지 않음). 14일 지나면 쓰지 않습니다. `--reset` 으로 지워집니다.
- "편집 중" 표시는 실시간이어야 해서 저장하지 않습니다(저장본 응답에는 비어 있음).
- 시간은 `%LOCALAPPDATA%\WJApp\app.log` 에 남습니다. 예: `[글] TW W40 0.01초 (저장본 1개 / 서버 0개)` ↔ `[서버] pullMany 3.2초`.

### 내가 쓴 글의 기록 (데이터 보관)
저장/일괄저장 요청은 `%LOCALAPPDATA%\WJApp\backup\saves_YYYY-MM.jsonl` 에 한 줄씩 남습니다(칸 주소, 내가 쓴 글, 서버 결과: `ok:버전` / `conflict` / `connection-failed`). 인터넷이 끊기거나 충돌이 나도 입력한 글이 사라지지 않습니다. 사진 칸은 내용 없이 길이만 남깁니다. 서버 쪽 전체 보관은 `pc_server` 의 백업/DB 를 쓰세요.

## 속도에 대해 (중요)

- **저장본이 없는 첫 호출은 서버 속도 그대로**입니다(서버가 같기 때문). 설치 직후 첫 화면, 매일 첫 로그인이 해당합니다.
- 앱이 빨라지는 곳: 저장본이 있는 화면 열기·화면 이동·글 채우기(v0.3), 서버가 끊겼을 때.
- 처음 호출 자체를 줄이려면 서버 쪽(PC 서버)을 바꿔야 합니다. 앱은 주소만 바꾸면 됩니다.
